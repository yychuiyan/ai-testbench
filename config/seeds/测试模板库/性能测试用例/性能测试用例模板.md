# 性能测试用例（场景）模板

## 一、场景设计字段

| 字段 | 说明 |
| --- | --- |
| 场景编号 | 格式 `PERF-三位序号` |
| 场景名称 | 如「核心下单链路基准场景」 |
| 业务配比 | 各接口/事务在混合流量中的占比（源自生产监控或运营预估） |
| 并发模型 | 虚拟用户数、思考时间（Think Time）、Ramp-up 策略 |
| 加压策略 | 基准 / 负载 / 压力 / 稳定性（长跑）/ 峰值脉冲 |
| 持续时间 | 负载场景一般 30 分钟，稳定性 4 小时以上 |
| 数据准备 | 测试数据量级与构造方式（避免缓存命中率失真） |
| 监控指标 | 应用（TPS/RT/错误率）+ 资源（CPU/内存/GC/连接池）+ 中间件 |
| 通过标准 | 可量化的验收阈值 |

## 二、场景模板

| 场景编号 | 场景名称 | 业务配比 | 并发模型 | 加压策略 | 持续时间 | 通过标准 |
| --- | --- | --- | --- | --- | --- | --- |
| PERF-001 | 核心链路基准 | 浏览:下单:支付 = 7:2:1 | 100 VU，思考时间 1-3s，Ramp-up 5min | 负载测试 | 30min | TPS ≥ 200；P95 RT ≤ 800ms；错误率 ≤ 0.1% |

## 三、通过标准的写法

- 吞吐量：`核心接口 TPS ≥ 目标值`（注明统计窗口，去掉 Ramp-up 阶段）
- 响应时间：用分位数而非平均值，如 `P95 RT ≤ 800ms，P99 RT ≤ 2s`
- 错误率：`业务错误率 ≤ 0.1%`（区分业务错误与系统错误）
- 资源水位：`CPU ≤ 75%，堆内存 Old 区占用无持续增长`（防内存泄漏）

## 四、场景选择策略

1. **基准测试**：单接口低并发，建立性能基线，用于回归对比。
2. **负载测试**：预期峰值 1.2 倍压力，验证容量达标。
3. **压力测试**：逐步加压直至拐点，找到系统极限与瓶颈点。
4. **稳定性测试**：0.8 倍峰值长跑 4h+，暴露内存泄漏与资源耗尽。
