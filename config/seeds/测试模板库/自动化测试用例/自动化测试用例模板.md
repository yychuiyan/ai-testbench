# 自动化测试用例模板

## 一、设计字段

| 字段 | 说明 |
| --- | --- |
| 用例编号 | 格式 `AUTO-模块缩写-三位序号` |
| 用例标题 | 可脚本化的场景名 |
| 优先级 | P0 / P1 / P2 |
| 自动化层级 | UI / API / 单元 / 端到端 |
| 前置条件 | 账号、权限、环境、依赖服务 |
| 测试数据 | 可参数化；避免硬编码与 flaky 数据 |
| 测试步骤 | 稳定、可重复；定位方式优先稳定选择器 |
| 预期结果 | 可断言的结果（状态码、关键字段、界面状态） |
| 断言点 | 明确断言对象与判定条件 |
| 清理动作 | 造数回滚、会话登出、临时文件删除等 |

## 二、样例表

| 用例编号 | 用例标题 | 优先级 | 自动化层级 | 前置条件 | 测试数据 | 测试步骤 | 预期结果 | 断言点 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| AUTO-LOGIN-001 | 正确账号密码登录成功 | P0 | UI | 测试环境可访问；账号可用 | 合法用户名/密码 | 1.打开登录页<br>2.输入账号密码<br>3.点击登录 | 进入首页；会话有效 | URL 含 /home；用户名展示正确 |

## 三、编写要点

1. **稳定性**：避免依赖动画时长、随机文案；等待用明确条件而非固定 sleep。
2. **断言**：每条用例至少 1 个可判定断言；失败信息可读。
3. **数据**：支持参数化；敏感信息不写入用例正文。
4. **清理**：有副作用的用例必须写清理或隔离策略。
5. **分层**：UI 覆盖主路径；接口/契约优先放 API 层。
